# Dogwood — TypeScript / WebAssembly Bindings

Typed WASM bindings for [Dogwood](https://github.com/dogwood-policy/dogwood), the Cedar-derived governance language for AI agents (temporal conditions + information providers).

Two shapes are exposed:

- **Batch operations** (`validate`, `lower`, `replay`, schema checks) — source strings in, typed report objects out. For policy authoring, CI, and tooling.
- **Live authorizer** (`DogwoodAuthorizer`) — lower once, feed events as they happen, get a decision per event with temporal history accumulating across calls. For agent gateways, MCP proxies, and anything deciding in real time.

The bindings wrap the same public surface of `dogwood-language` that the CLI drives. `ops.rs` and `error.rs` are verbatim from `dogwood-cli` — drift is a compile error, not a behaviour difference.

## Layout

```
dogwood-wasm/
├── src/
│   ├── lib.rs          # wasm-bindgen surface (batch ops + error projection)
│   ├── live.rs         # stateful DogwoodAuthorizer class
│   ├── ops.rs          # frontend operations (verbatim from dogwood-cli)
│   ├── error.rs        # miette → structured diagnostic (verbatim from dogwood-cli)
│   └── providers.rs    # wasm-specific guard on provider declarations
├── pkg/                # generated by `npm run build` (git-ignored)
├── test.cjs            # batch-operation smoke tests
├── test-live.cjs       # live-authorizer semantics (parity with replay)
├── test-coverage.cjs   # full surface coverage (every function, field, error path)
├── example.ts          # strict-mode type-check of the generated .d.ts
└── package.json        # build / test / typecheck scripts
```

## Build

Requires Rust ≥ 1.85 (edition 2024), the wasm target, `wasm-pack`, and Node ≥ 16.

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-pack

cd dogwood-wasm
npm run build                   # → pkg/ (Node/CommonJS target, uses wasm-pack)
npm install && npm run verify   # runtime tests + tsc --strict typecheck
```

Other targets: `npm run build:bundler` (Vite/webpack, ESM) and `npm run build:web` (no bundler).

## Batch Operations

All take source strings and return typed report objects. Fatal errors are thrown as `DogwoodError`; non-fatal findings come back in the report.

| Function | Purpose | Returns |
|---|---|---|
| `checkParse(src, …)` | parse + macro-expand | `CheckParseReport` |
| `validate(src, actionSchema, …)` | lower + type-check | `ValidateReport` |
| `lower(src, actionSchema, …)` | emit Cedar artifacts | `LowerArtifacts` |
| `replay(src, actionSchema, log, …)` | lower + replay a `.log` trace | `ReplayReport` |
| `checkActionSchema(src)` | validate a `.cedarschema` | `SchemaCheckReport` |
| `checkEventSchema(src)` | validate a `.dwschema` | `SchemaCheckReport` |
| `checkProviders(json)` | validate a `providers.json` | `SchemaCheckReport` |
| `mcpToCedarSchema(json)` | MCP `tools/list` → Cedar action schema | `string` |

The trailing `eventSchema? / providers? / macros?` arguments are optional service-schema overrides. Omit for defaults.

```js
const dw = require("./pkg/dogwood_wasm.js");

const actionSchema = `namespace Drupe {
  entity User; entity Gateway;
  action "Read" appliesTo {
    principal: [User], resource: [Gateway],
    context: { input: { document: String, user: String } }
  };
}`;

const policy = `permit(principal, action == Drupe::Action::"Read", resource)
when { context.input.document like "*report*" };`;

const report = dw.validate(policy, actionSchema);
console.log(report.passed); // true
```

## Live Authorizer

```js
const auth = new dw.DogwoodAuthorizer(policy, actionSchema);

const decision = auth.isAuthorized({
  action: "Drupe::Action::Read",
  kind: "request",
  timestamp: Math.floor(Date.now() / 1000),
  principal: { type: "Drupe::User", id: "alice" },
  resource:  { type: "Drupe::Gateway", id: "gw1" },
  logged:  { input: { document: "quarterly report", user: "alice" } },
  context: { input: { document: "quarterly report", user: "alice" } },
  entities: [{ type: "Drupe::User", id: "alice", attrs: { dept: "eng" } }],
});

if (!decision.allowed) throw new Error("denied");
```

History-only events (anything other than `kind: "request"` by default) return `undefined` — they update temporal state but yield no verdict.

### Key Semantics

- **Timestamps are seconds**, not milliseconds. A `within 1h` window is 3600. Passing `Date.now()` raw inflates every window by 1000×.
- **`logged` and `context` are distinct.** `logged` is the durable temporal record; `context` is the ephemeral Cedar request bag. A field both need (typically `input`) must appear in both.
- **Entity references are structured** (`{ type, id }`), never string literals. The id is escaped exactly once — no double-escaping footgun.
- **A deny with non-empty `errors`** is a fail-closed evaluation failure, not "policy said no."

### Input Validation

The authorizer rejects (without observing into history):

| Rejected | Why |
|---|---|
| Unknown action | Would silently deny with empty `errors`, indistinguishable from "policy said no" |
| Unknown kind | Would return `undefined` forever — nothing is ever authorized |
| Backwards timestamp | Would silently produce wrong temporal answers |
| Interior `::` in action id | Would resolve to nothing via the `::` split |

Introspection getters (`actions`, `eventKinds`, `decisionKinds`, `lastTimestamp`) let a host verify its wiring at startup.

### Lifecycle

`DogwoodAuthorizer` owns wasm-heap memory that GC does not reclaim. Free it explicitly:

```ts
const auth = new DogwoodAuthorizer(policy, actionSchema);
try { /* … */ } finally { auth.free(); }

// or with explicit resource management (TS ≥ 5.2):
using auth = new DogwoodAuthorizer(policy, actionSchema);
```

`reset()` drops accumulated history and re-lowers the same sources. `decisionCount` tracks decisions returned.

## Errors

Fatal failures throw a `DogwoodError` with structured `.diagnostic`:

```ts
import { validate, type DogwoodError } from "./pkg/dogwood_wasm.js";

try {
  validate("permit(", actionSchema);
} catch (e) {
  const err = e as DogwoodError;
  // err.diagnostic: { message, severity, code?, labels[], help?, related? }
}
```

Byte offsets in `labels` index the source string you passed in.

## Information Providers

Rhai providers work — the interpreter compiles to wasm. But the script must be **inline** (`implementation.script`). A `scriptFile` reference is rejected up front with an actionable error, because `wasm32-unknown-unknown` has no filesystem and an unresolvable reference would silently fail closed at authorize time.

## Testing

`npm run verify` runs 89 assertions across three suites plus `tsc --strict`.

| Suite | Coverage |
|---|---|
| `test.cjs` | Smoke: does each batch operation work? |
| `test-live.cjs` | Replay-parity: does the live authorizer produce identical verdicts to `replay` on the same scenario? |
| `test-coverage.cjs` | Every exported function, field, optional argument, error path, and value-conversion branch |

## Limitations

- Dogwood is a **reference interpreter, not for production**; these bindings inherit that.
- The `net` feature (HTTP providers) is off — cannot work in wasm.
- **Temporal history is never pruned.** Growth is ~1.6 KB/event with no plateau. Long-lived instances must `reset()` periodically or cap their lifetime.
- The live authorizer's input checks do **not** apply to `replay` (which uses the frontend's internal parser). A bare action id or backwards timestamps in a `.log` trace pass through unremarked.
- Module size is **~8.7 MB** (~2.6 MB gzipped). Cedar, Rhai, and the parser dominate.
